# 直播通知

一个 Chrome Manifest V3 扩展：监控斗鱼与 B 站的直播间，把「开播了」「弹幕里出现我在等的东西」「这个房热起来了」「弹幕突然爆了」「斗鱼切出了新的看点」五件事做成桌面通知。

不登录任何平台账号，全部通过匿名公开接口轮询与弹幕连接获取数据，所有设置只存在本地浏览器里。

## 功能

| 通知 | 触发时机 | 数据来源 | 默认参数 |
| --- | --- | --- | --- |
| **开播通知** | 房间由未开播变为开播 | 轮询房间状态 | 每 60 秒一轮（可调，最小 60 秒） |
| **弹幕检测** | 房间弹幕命中检测词，窗口内条数达到阈值 | 弹幕长连接 | 阈值 5 条 / 窗口 5 分钟 / 冷却 10 分钟 |
| **观众数提醒** | 贵宾数（斗鱼）或高能榜在线数（B 站）从阈值以下升到阈值以上 | 10 分钟一次的采样短连 | 阈值 1000，逐房配置 |
| **弹幕激增提醒** | 上一分钟弹幕条数达到本场基线的数倍，且基线本身足够活跃 | 弹幕长连接 | 3 倍 / 门槛 3 条每分钟 / 冷启动 10 分钟 / 冷却 30 分钟 |
| **看点通知** | 斗鱼房间切出新的看点（平台 AI 事后生成，实测约 10–25 分钟一条） | 每 5 分钟轮询斗鱼看点接口 | 开关逐房配（默认关），周期固定 5 分钟 |

五个功能彼此独立：各自有全局总开关 + 房间级开关，关闭总开关后已配的参数保留，重新打开即恢复。关闭其中一个不影响另外四个。

除此之外：

- **弹窗**：在线主播列表（昵称、标题、封面、观众数），点击直接进直播间，扩展图标上的角标显示在线数量。
- **设置页**：房间增删与拖拽排序、轮询间隔、两个平台的观众数采样开关、各项通知参数。
- **跟随系统深浅色**：界面按 `prefers-color-scheme` 自动切换，无需手动设置。
- **当前标签页跳转**：默认新开标签页，可在弹窗里改成复用当前标签页。

## 支持平台

| 平台 | 开播通知 | 弹幕检测 | 弹幕激增 | 看点通知 | 观众数指标 |
| --- | --- | --- | --- | --- | --- |
| 斗鱼 | ✅ | ✅ | ✅ | ✅ | 贵宾数（`oni`） |
| B 站 | ✅ | ✅ | ✅ | — | 高能榜在线数（`ONLINE_RANK_COUNT`） |

表格里的 `—` 表示平台没有这个形态的信息：看点（平台 AI 切出的带标题精彩片段）是斗鱼独有的，B 站没有对应物。

浏览器要求：Chrome 或 Edge 等 Chromium 内核浏览器（Manifest V3，`chrome.action` / service worker）。

## 安装

扩展暂未上架应用商店，从源码加载即可：

```bash
git clone https://github.com/bestyy/douyu-extension.git
```

1. 打开 `chrome://extensions/`（Edge 为 `edge://extensions/`）
2. 打开右上角的**开发者模式**
3. 点击**加载已解压的扩展程序**，选择仓库根目录（含 `manifest.json` 的那一层）
4. 扩展图标固定到工具栏

更新：`git pull` 后回到扩展页点一次刷新按钮即可。

## 使用

1. 点扩展图标打开弹窗，进入**设置页**。
2. 在「房间号管理」里选择平台、输入**纯数字房间号**并添加。昵称会自动解析；解析失败说明房间号有误。
3. 点房间行内的**通知设置**配置这个房间：开播通知开关、检测词与阈值、观众数提醒阈值、弹幕激增开关、看点开关。拖动行首手柄可以调整顺序。
4. 各功能的全局开关与参数在下方几张卡片里。

弹幕检测示例：给某房配置检测词「组队」「开黑」，阈值 5 条、窗口 5 分钟。开播期间该房弹幕里任一词命中（子串匹配、不区分大小写）累计到 5 条，就发一条通知；之后进入 10 分钟冷却，避免同一波弹幕反复打扰。

弹幕激增通知的正文是两行：第一行报条数（`上一分钟 120 条，平时约 15 条`），第二行附上那一分钟里最长的合格弹幕，用来判断现在在聊什么。刷屏的「666666」「哈哈哈哈」和两三个字的短句会被跳过；如果那一分钟全是复读，就只报条数，不留第二行。

看点通知只有斗鱼房间有（B 站没有这个形态的信息）。首次给某个房打开开关时只记录当前进度，不会把这个房已经积累的看点补报一遍；此后出现编号更大的看点才通知，一轮里发现多条只报最新那条，正文补一行「另有 N 条」。所以隔了很久再打开开关，最多也只收到一条。

## 工作原理

- **轮询**：`chrome.alarms` 按设定间隔（默认 60 秒）批量拉取房间状态，合并进本地房间库，检测开播边沿。
- **观众数采样**：每 10 分钟做一次短连接弹幕 WebSocket 会话——连上、收到贵宾数 / 高能榜数据、立即断开，平时不保持连接。
- **弹幕盯守**：只有**开播**且**配了检测词或开了激增提醒**的房间才保持长连接，下播即断开。同时最多盯守 **5 个**开播房间，超出的按房间列表顺序排队，弹窗会提示排队中的房间。这一条长连接同时供给弹幕检测与弹幕激增两个功能，不会为它们各开一条连接。
- **看点取数**：每 5 分钟一次独立的接口轮询（周期写死，不随「轮询间隔」变化），只查**开了该房看点开关且当前开播**的斗鱼房间，不建立任何连接、不占用盯守名额。斗鱼返回的是这个房本场的**全量看点列表**，因此「什么算新的」按每房**已通知过的最大看点编号**判定，水位存在本地（重新打开开关即接着上次的水位走）。
- **B 站通道选择**：检测到 `SESSDATA` Cookie 时视为已登录，此时 service worker 直连弹幕 WebSocket 必定被风控（错误码 1006），因此改由 `live.bilibili.com` 页面上的 content script 桥接转发；未登录时直接用 service worker 直连。

架构决策与理由记录在 `docs/adr/`，领域术语见 `CONTEXT.md`。

## 隐私

- 扩展**不收集、不上传任何数据**，没有自建服务器，所有请求都由浏览器直接发往斗鱼 / B 站的公开接口。
- 房间、主播快照与全部设置存放在 `chrome.storage.local`，仅存在于本机浏览器配置中，卸载扩展即清除。
- 权限用途：`storage`（保存配置）、`alarms`（定时轮询）、`notifications`（桌面通知）、`cookies`（仅用于读取 `SESSDATA` 是否存在，判断 B 站登录态以选择弹幕通道，不做他用）。

## 开发

无需构建步骤，源码即产物。测试使用 Node 内置测试运行器：

```bash
npm test        # node --test，188 个用例
```

测试在进程内组装真实的房间库、编排与规则模块，只把存储、平台 API、弹幕客户端、通知、alarm、标签页替换成内存实现，覆盖五条通知链路、B 站通道降级、单写者并发与 service worker 入口装配。

```
background.js                 service worker 入口：组装依赖 + 接线 chrome 事件
lib/room-identity.js          房间标识：复合键的拼与拆、房间号校验、每个平台的房间事实（零依赖词汇）
lib/orchestrator.js           编排：轮询 / 采样 / 盯守 / 通知判定与发送
lib/room-store.js             房间库：rooms / streamers / settings 的唯一写入者
lib/storage.js                chrome.storage.local 的薄适配
lib/douyu-api.js             斗鱼房间状态接口
lib/bilibili-api.js          B 站房间状态接口
lib/douyu-barrage.js         斗鱼弹幕客户端（采样 oni / 检测 chatmsg）
lib/bilibili-barrage.js      B 站弹幕客户端（采样 ONLINE_RANK_COUNT / 检测 DANMU_MSG）
lib/bili-bridge-channel.js   B 站页面桥接通道（登录态下走页面转发）
lib/danmaku-watch.js         弹幕检测规则：检测词匹配、滑动窗口计数、盯守名额
lib/viewer-alert.js          观众数提醒规则：阈值归一化与上升边沿判定
lib/danmaku-surge.js         弹幕激增规则：分钟桶、基线中位数、样本弹幕、冷却
lib/highlight-alert.js       看点通知规则：平台门、总开关、按每房看点水位挑出新看点
options/                     设置页
popup/                       弹窗
test/                        node --test 用例与共享 harness
docs/adr/                    架构决策记录
CONTEXT.md                   领域术语表
```

规则模块（`danmaku-watch` / `viewer-alert` / `danmaku-surge` / `highlight-alert`）是纯计算、不引用 `chrome` 与 WebSocket 的 UMD 模块，service worker 用 `importScripts` 加载、Node 用 `require`、页面当普通 script 引入，因此可以直接在测试里构造。`room-identity` 同样是零依赖的 UMD 模块，承载房间身份（复合键、房间号校验、平台事实），要求排在所有使用它的 module 之前加载（判据见 `docs/adr/0005`）。

## 已知限制

- **盯守名额上限 5 个**：同时开播且需要盯守的房间超过 5 个时，排在后面的不建立弹幕连接，弹幕检测与弹幕激增都不生效，弹窗会列出排队中的房间。上限存在是因为多房间并发长连接容易触发平台限流。
- **弹幕激增有冷启动**：每场开播后要先积累若干个完整分钟桶才开始判定（「冷启动时长」，2–30 分钟，默认 10），所以一场不到约 15 分钟的房间基本不会触发——这是为了避免把开播爬坡误判成激增。调小可以更早发现激增，代价是开播爬坡更容易被误报。
- **观众数提醒的实时性上限是 10 分钟采样周期**：短时高峰可能刚好落在两次采样之间而看不到。
- **弹幕激增统计的是真实弹幕条数**，不是平台的「热度 / 人气」加权值（后者含礼物、推荐位、观看时长等权重，不等于弹幕量）。
- **看点通知的节奏由平台决定，且天然滞后**：看点由平台 AI 事后切出（实测约 10–25 分钟一条），通知本来就晚于直播画面几分钟；直播中也可能长期一条都没有，所以开了开关长时间没收到通知是正常的。未开播时平台不返回看点列表，扩展也就不查这个房（离线查也查不到，不算漏）。取数失败或返回空列表时不写水位，下次成功仍会通知最新那条。
- 斗鱼有未开播上报贵宾数 0 的兜底，B 站没有，因此两平台在下播清空存量上的表现略有差异；扩展用「连续两轮轮询确认离线」来清空，以抗单次接口抖动。
- 依赖平台公开接口，接口或风控策略变更可能导致对应功能失效；此类问题需要跟随平台调整。
