# 斗鱼靓号房间的线上取数一律走内部房间号，身份仍是用户输入的号

斗鱼弹幕服务器与 `betard` 接口一样只认内部 `room_id`：拿靓号 `joingroup` 等于订阅了一个不存在的房间。2026-10-04 实测（`danmuproxy.douyu.com:8501`，靓号 `91224` / 内部号 `8727436`）：用靓号只回 `loginres` 与 `defense_tower_session`，25 秒内没有**任何**房间消息；用内部号则 `chatmsg`、`uenter`、`oni`（`vn=277`）等全量到达，且该 `oni` 自带的 `rid` 是内部号 `8727436`。也就是说 ADR-0015 记为「已知、可接受的降级」的那条后果是真的：靓号房间的贵宾数采样、弹幕检测、弹幕激增全部静默失效（既没有 `oni` 也没有 `chatmsg`）。HTTP 侧的看点接口同样只认内部号，此前靠内存缓存被轮询预热，冷 SW 下一样取不到。

因此本决策：**斗鱼房间的每一条平台线上请求都用内部房间号，存储与回调的身份始终是用户输入的号**。三处落地：

- `rooms[].internalRoomId` 是内部号的持久化处，由每轮轮询的取数结果刷新——`fetchRoomInfo` 成功时回传实际查询的 wire 号，房间库合并时写回条目。它是平台派生的观测值，不进配置备份（与 `streamers` / 看点水位同类，见 ADR-0012）。
- 弹幕客户端经构造注入的 `resolveInternalRoomId` 端口取内部号（装配根实现为「读房间库只读快照里该房的 `internalRoomId`，缺则回退输入号」），WebSocket 的 `loginreq roomid@=` / `joingroup rid@=` 用内部号；`state.roomId` 与所有回调仍报存储里的号。
- 看点取数由调用方把 `internalRoomId` 传下去，`fetchHighlights` 不再自行查内存缓存。

要点三条：

- **回调必须回映成存储号**。线上 `oni` 自带的 `rid` 是内部号，拿它当存储键会挂不上房间、观众数丢失；回调一律用连接建立时记下的存储号。
- **缺省即降级，不阻塞也不报错**。老房间（条目里没有 `internalRoomId`）或解析失败时回退用输入的号连——等同于今天的行为，下一轮轮询成功即自动补齐（懒回填，不写迁移代码）。
- **身份不替换**。`roomId` 仍是用户输入的靓号（ADR-0015 的领域定义不变），内部号只是一条并存的派生字段。

## Considered Options

- **内部号持久化在房间条目 + 客户端注入端口读取（选用）**：SW 冷启也不再丢映射（内存缓存随 SW 回收即失，而 10 分钟采样 alarm 大概率是冷启），弹幕客户端与存储解耦（端口注入），纯规则 module 不受影响。
- **只用 `douyu-api` 的内存缓存（沿用 ADR-0015 现状）**：改动最小，但映射随 SW 回收即丢；采样 alarm 冷启时靓号又退回用靓号连、毛病复现，等于没修。
- **解析出的内部号直接替换存储里的 `roomId`**：下游全部透明、最省心，但在用户背后换掉了输入号，与「房间号是用户输入」的领域定义冲突，ADR-0015 已否决。
- **弹幕客户端连上失败后再回退解析重连**：不用预先持久化，但每个靓号房间每轮都要先白等一次采样超时（20 秒）才重试，且检测长连接丢掉的 `chatmsg` 无法这样补救。

## Consequences

- 斗鱼房间多一个派生字段 `rooms[].internalRoomId`，`fetchRoomInfo` 的返回多一个 `data.internalRoomId`（实际查询的 wire 号，普通房间与回显的 `roomId` 相同）。房间库的轮询合并从「只写 `streamers`」变成也写 `rooms` 的这个字段，仍是单写者。
- 配置备份显式剥掉 `internalRoomId`（`projectRoom` 目前透传未知字段，不剥会跟着导出）；导入后下一轮轮询自动补齐。
- 盯守路径（轮询后立即收敛）与弹幕客户端共用同一份映射解释；`probeOnline` 超时兜底仍走 `fetchRoomInfo` 自行解析，不依赖持久化值。
- 同一间房若被用户同时以靓号和内部号添加，会各建一条连接、连同一个内部号，各自独立计数——不合并（房间身份是 `platform + 房间号`，两条都是用户的显式输入）。
- ADR-0015 同族的问题（`fetchHighlights` 依赖内存缓存）一并收干；`VANITY_ROOM_ID_CACHE` 只剩「避免每轮重复拉房间页」这一个职责，不再是跨模块的映射来源。
