# 抖音未知状态 ≠ 未开播：保留上次状态并退避重试

抖音 `web/enter` 在风控或网络异常时返回 HTTP 200 **空 body**（无签名/被限流时），或 503（页面/首页端点被限流）。这类响应无法确定房间是否开播，语义上属于**未知状态**（参考 douyinLive 文档："unknown 不等于未开播"）。若把未知当作"未开播"，会在风控期间向用户误发"已下播"通知——而实际主播可能仍在直播。

决定：未知状态下**保留该房间上一次已知状态**（不写 `offline`，不触发下播通知），对失败请求做指数退避重试（如 10s→30s→60s），必要时刷新 `ttwid` cookie 后重试。只有**确定**的 `status=4` 才视为已关播。连续多次未知（超过退避上限）仍保留上次状态，等待下一轮轮询自然恢复。

## Considered Options

- 未知 → 保留上次状态 + 退避重试（选用）：避免误报下播，代价是实现稍复杂、极端情况下状态可能滞后。
- 未知 → 直接标记离线：实现简单，但风控期间可能向用户误发"已下播"通知，损害通知可信度。

## Consequences

- 弹窗/设置页在"未知"期间显示的是上次已知状态（可能滞后），但不会出现假的下播通知。
- 退避与 ttwid 刷新逻辑需在 `DouyinAPI` 内实现，与现有斗鱼/B站轮询（失败保留旧数据）行为保持一致。
