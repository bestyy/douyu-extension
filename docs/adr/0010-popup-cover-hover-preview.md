# 弹窗卡片的圆形封面，悬停时浮出 16:9 完整画面预览；B站封面源改为 keyframe 优先

「不点进直播间也能看出在播什么」这个诉求，直觉做法是把卡片上那张 44px 圆图原地放大。但那张圆图是**直播画面封面**（斗鱼 `room_src` / B站 `user_cover`）被圆形裁切后剩下的画面中心一小块——原地放大圆形，放大出来的还是那一小块像素，看不出内容，回答不了诉求。因此改为：悬停卡片时，盖在卡片上居中浮出一张 16:9 的完整封面（约 260×146）。它消费的封面原图斗鱼是 1280×720 的画面截帧、B站是 1280×720 的 `keyframe`（当前画面帧），足够清楚。B站的 `coverUrl` 顺带从 `user_cover`（470×264 官方封面图）改为 `keyframe || user_cover`，让卡片圆图与预览都拿到「当前画面」而不是官方封面图。

## Considered Options

- **原地放大圆形封面**：最贴合「把头像放大」的字面说法；但圆形的裁切没有解除，放大的是画面中心那一小块，看不出在播什么——达不到诉求本身。
- **卡片原地展开成 16:9 大图（不浮层）**：不遮挡邻近卡片、不越界；但列表会随悬停跳动、每张卡片高度不一致，观感更差。
- **B站封面源不改（继续 `user_cover`）**：零改动；但 470×264 官方封面缩到 260px 虽仍清晰，看到的是「官方封面图」而不是「当前画面」，与诉求的「正在播什么」有偏差。
- **B站前端派生 keyframe（存储仍存 `user_cover`）**：不改所存值；但多一条只在预览层生效的派生规则，卡片圆图与预览会看到两张不同的图，两处封面源分裂。
- **浮层跟随鼠标 / 贴在卡片旁（出界翻边）**：少盖卡片；但跟随鼠标在「鼠标扫过整排卡片」时很显躁，贴边方案要按卡片位置算坐标（浮层须挂在滚动容器外用 fixed 定位），实现面更大。
- **悬停立即出现**：最跟手；但鼠标扫过一整排卡片会连续闪出/收起。
- **加全局开关**：可随时关掉；但一个纯视觉、无副作用、不写盘的行为，为此新增设置项 + 存储键 + 消息链路不划算。

## Consequences

- **不新增任何存储键、设置项或消息链路**：预览是弹窗内的纯展示行为，弹窗仍是只读展示面（ADR-0003 的单写者边界一行未动）。
- 预览浮层 `position: absolute` 落在 `.streamer-card`（`position: relative`）内，越出右侧滚动容器的部分由该容器裁掉；预览比卡片高（146px vs 约 66px），列表首尾几张会露出一半，故出现前按容器把中心**垂直**夹进可视区（横向 260px 在列表列内放得下，不夹）。
- 移开**整张卡片**才收起（而非移开头像就收）：预览盖住的正是头像位置，鼠标一挪去细看就会消失，所以绑定在卡片的 `mouseleave` 上。
- 「拿不到封面就不弹」：`coverUrl` 为空、或图片加载失败回退占位图时，悬停不出预览（把 44px 占位图标放大到 260px 只是噪声）。判断依据是卡片 `<img>` 的 `hasCover` 标志，与卡片回退占位图同一处逻辑。
- **B站封面源从 `user_cover` 改为 `keyframe || user_cover`** 是本次唯一的既有行为改动：升级后需等下一轮轮询（≤「轮询间隔」）才更新存储里的封面；部分房间没有 `keyframe`，自动回退 `user_cover`，不会因此拿不到封面。斗鱼不需要改（`room_src` 本来就是画面帧）。
- 词表新增两个词条：**封面**（`streamers[].coverUrl`，平台给的直播画面，是卡片圆图与悬停预览的来源）与**主播头像**（`streamers[].avatarUrl`，平台给的人像，当前界面不显示）。两者此前在文档里都缺词条，卡片上那个圆图容易被误当成「头像」，故一并厘清。
- 设置页不受影响：它从不在卡片上渲染封面，本次改动只在弹窗。
