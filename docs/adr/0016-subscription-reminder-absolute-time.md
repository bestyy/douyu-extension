# 订阅：绝对时刻的一次性提醒，独立存储、触发即删、不受房间移除与配置导入影响

用户要能「订阅明天 3 点某个房间，到点弹通知叫我去他的直播间」。这条功能引入一个新领域概念「订阅」（词条见 CONTEXT.md），它是一份独立于房间配置的排定事件。下面九件事互相牵制，合记一条 ADR。

**一、订阅是一次性绝对时刻，不是重复日程。** 记录形状 `{ id, platform, roomId, at }`，`at` 是绝对时间戳（本地时区只在用户输入的那一刻解释一次，此后改系统时区不改动已排定的时刻）。触发一次即删除，列表里永远只剩待触发的；只接受未来时刻（输入时早于当前即拒绝），不设提前上限。不引入「每天 / 每周」重复语义——「明天 3 点」是具体时刻，一次性模型没有「有效期 / 结束条件 / 下一次算哪天」这些概念，最简；将来若要重复，是在它之上叠一层规则，不是改写这个实体。

**二、到点无条件发，通知正文报当前开播状态。** 不拿开播状态决定发不发：用户要的是「到点提醒我去」，像闹钟，约定了时刻就该响。但正文附上触发时的开播状态——在播则「正在直播：<标题>」，未播则写明「当前未开播」；这份快照每轮轮询本来就有，成本极低，能让人一眼决定去不去。不选「只在开播时才发」（主播晚开一分钟就收不到，违背「到点提醒」）；也不选「未开播则等开播补发」（要引入「等待中」状态、等待上限与超时清空，复杂度最高）。

**三、错过补发有固定 5 分钟宽限期。** 到点那一刻扩展可能没在运行：MV3 的 SW 会被回收，浏览器也可能正关着，alarm 的实际触发时刻因此可能晚于订阅时刻。裁决口径：晚不超过 5 分钟照发，超过则静默丢弃——几分钟的延迟补发仍有用，睡一觉醒来才弹的过时提醒是噪音。宽限期是纯裁决模块自带的固定常量，不暴露给用户、不做成设置项（照 ADR-0005：判定所需的常量自带）。**本设计不依赖「错过的一次性 alarm 会不会被 Chrome 补触发」这条外部事实**：无论 Chrome 补不补，SW 每次启动都从存储重排 alarm，触发时再按宽限期逐条裁决，两种情况下的结果都正确。

**四、订阅独立存储，是房间库的第五个键 `subscriptions`。** 房间库（ADR-0003）从四键扩为五键的单一写入者，订阅增删与「触发后删除 / 错过丢弃」都是它的意图式操作。不把订阅塞进 `rooms[].reminder`：一个房间可能要排多条订阅、订阅有自己的生命周期（创建 → 触发 → 删除），做成房间字段会把「房间配置」与「排定的事件」混为一谈，也限制了一房一条。代价是「房间库」的定义要扩写（CONTEXT.md 的「房间库」词条已随之更新，`lib/room-store.js` 文件头与相关注释里的「四个键」也要改）。

**五、订阅独立于房间列表：房间被移除不影响订阅。** 订阅自足持有 `platform + roomId`，删房间不级联删订阅——用户删掉一个房间的监控，未必想取消一个已经约好的提醒。到点照常提醒、点击照常进直播间。房间已不在列表时，界面上的显示名回退为「平台 房间号」（用不了昵称就退到复合键，不让列表出现空白）。反方向收紧：创建订阅时只能从已在扩展里的房间中选，不支持手输未添加的房间号。

**六、不进配置备份，导入配置时保留现有订阅。** 配置备份（ADR-0012）只搬 `rooms` / `categories` / `settings`，`subscriptions` 不进文件：它是「用户排定的一次性事件」而非「可长期搬走的配置」，换机器后重排更合理，也避免给导出文件多养一处 schema 与版本。相应地，导入是整体替换那三键（外加 `streamers` 对齐），订阅列表原封不动——连「清空编排运行时键」那一步也不碰它（它归房间库、不归编排）。若日后要纳入备份，需升文件 `version` 并加一处 schema 校验。

**七、通知 ID 按订阅唯一，点击进直播间。** 既有五种通知都「按房间复用 ID 覆盖、不堆积」，订阅不能这样——同一房间可以有多条订阅，按房间复用 ID 会互相覆盖。故 ID 形如 `<platform>_<roomId>_sub_<订阅 id>`：`<platform>_<roomId>` 前缀让既有的「剥后缀还原房间复合键」逻辑照常拿到直播间 URL，`_sub_<id>` 保证唯一。这要求扩解析侧：`ORCHESTRATOR_NOTIFICATION_SUFFIXES` 现在是一张**精确匹配**的后缀表，而 `_sub_` 后面跟的是变长 id，因此要在「剥已知后缀」之外补一条「在 `_sub_` 处截断」的规则（`liveUrlFromNotificationId`）。

**八、单个 alarm 承载全部订阅，按最早待触发时刻装填，随列表收敛重建。** 不为每条订阅各建一个 alarm（订阅数无上限，逐条创建与清理都更杂）：用**一个**一次性 alarm 排在「最早一条待触发订阅的 `at`」，SW 启动 / `onInstalled` / `onStartup` / 订阅增删 / 一次触发之后都收敛重排。收敛沿用 ADR-0011 的 `alarms.get` 口径判存在性（内存标志活不过 SW 回收）；且必须每次都从存储重排、不假设 alarm 还在——扩展更新会清 alarm，浏览器重启也只被「大致」保证（见 `lib/orchestrator.js` 关于 `ensurePeriodicAlarm` 的说明）。一次触发时扫出所有 `at <= now` 的订阅，逐条按宽限期裁决、发通知、删除，再排下一批。

**九、落点：房间库两个操作 + 一个纯裁决模块 + 一个新的收敛入口 + 设置页一张卡片 + popup 顶部一行。** 订阅增删是房间库的意图式操作；「这条该不该发、文案怎么写」抽成零依赖纯裁决模块（照 ADR-0005），生产与测试共用；编排新增一个 alarm 名与其 `onAlarm` 分支、一个把 alarm 排到最早订阅时刻的收敛函数（进 `convergeRuntime` 的序列）；设置页新增「订阅」卡片（列表只读 + 删除；添加＝选房间 + 选日期时间）；popup 顶部在下一条订阅存在时显示一行「下一条：昵称 时间」，仍只读、不写任何键，不改 ADR-0009 的纪律。订阅通知只受全局 `settings.notificationsEnabled` 控制，不新增 per-feature 总开关——订阅本就是用户主动创建的一次性低频提醒，专用开关是多余的配置面。

## Considered Options

- **重复日程（每天 / 每周）**：适合固定作息、省得逐次添加；但「明天 3 点」这类一次性需求要另加有效期与「下一次算哪天」的规则，模型更重。故取一次性绝对时刻。
- **只在开播时才发 / 未开播则等开播补发**：都更贴心；但前者在主播晚开一分钟时就违背「到点提醒」的承诺，后者要引入等待状态与超时裁决。故取「到点无条件发 + 正文报状态」。
- **错过一律补发 / 一律丢弃**：前者会把休眠数小时后的过时提醒弹出来，后者在 MV3 下 SW 一被回收就永远收不到。故取固定 5 分钟宽限期。
- **存进 `rooms[].reminder`**：复用现有 per-room 面板与 `patchRoomConfig`、改动最小；但一个房间只能一条，且把「排定的事件」塞进「房间配置」。故取独立的 `subscriptions`。
- **删房间时级联删订阅**：避免「房间列表里没有、却弹出提醒」的困惑；但用户删房间未必想取消已约的提醒。故取订阅独立存活。
- **订阅进配置备份**：换机器保留提醒；但它是一次性事件而非长期配置，且要给导出多养 schema 与版本。故不进备份，导入时保留。
- **每条订阅一个 alarm**：触发时可直接定位到是哪条；但订阅数无上限，逐条创建 / 清理更杂。故取单个 alarm 排在最早时刻。
- **新增 `settings.subscriptionEnabled` 总开关**：与其它 per-room 功能的惯例一致；但订阅本就用户主动创建、低频、不自动重复，专用开关只增加配置面。故沿用 `notificationsEnabled`。

## Consequences

- 房间库从四键扩为五键：新增 `subscriptions` 的增删与「按时刻取待触发 / 删除已触发或错过」的操作；`lib/room-store.js` 文件头、`ROOM_STORE_DEFAULTS` 注释与 `snapshot()`（要带上订阅，供设置页与 popup 读）随之改动；`test/room-store.test.cjs` 扩写。
- CONTEXT.md 新增「订阅」「订阅通知」两个词条；「房间库」词条已改为五键（与本 ADR 同步落地）。
- 新增零依赖纯裁决模块（宽限期判定 + 通知标题/正文构造）与对应测试；它自带宽限期常量，不引用其它 lib。
- 编排新增一个 alarm 名与 `onAlarm` 分支、一个订阅收敛函数（排到最早待触发时刻），并在 `start()` / `onInstalled` / `onStartup` / 订阅增删消息 / 一次触发后调用；沿用 ADR-0011 的 `alarms.get` 收敛口径。
- `liveUrlFromNotificationId` 与后缀表要支持变长的 `_sub_<id>` 后缀（在 `_sub_` 处截断还原房间复合键）；既有的通知点击用例要补订阅一例。
- 设置页新增「订阅」卡片（列表只读 + 删除、添加表单＝房间下拉 + 日期时间输入、拒绝过去时刻）；`options.css` 补卡片样式。
- popup 顶部新增「下一条订阅」只读行（读房间库快照取最早待触发的一条，房间已移除则显示「平台 房间号」）；不新增任何写入。
- 配置备份不动：`ConfigBackup.ROOM_KNOWN_FIELDS` / `SETTINGS_SCHEMA` 与文件 `version` 都不变；房间库的导入操作必须显式不触碰 `subscriptions`（现有导入只写 rooms/categories/settings 并对齐 streamers，新增的第五键需确认不在其写入范围）。
- 订阅不进 `settings`，故 `ROOM_STORE_SETTINGS_KEYS` 与备份 schema 都不变，也不新增全局开关。
