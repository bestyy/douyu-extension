# 「今日统计」随数据源停服整体下线，扩展不再依赖任何第三方数据站

ADR-0007 引入了本项目唯一一处非斗鱼 / 非 B 站的第三方数据源——数据站 doseeing（在看直播）的 `GET /api/room_stat?room=<房间号>&hours=today`，用来在弹窗里显示斗鱼房间「当天 0 点起累计」的弹幕数 / 弹幕人数 / 礼物金额 / 礼物人数。该 ADR 的 Consequences 已写明它的代价与风险：数据可用性完全不由本项目掌控，站点挂掉即数字不显示。这个风险在 2026-09-30 兑现——doseeing 全线停止服务，公告原文为「因业务调整，自 2026 年 09 月 30 日起，在看直播排行榜及相关服务号、小程序、APP 的直播数据服务全线停止」。因此本条 ADR 记录的是**把「今日统计」整体下线**这一决定，并取代 ADR-0007。

判定依据（2026-10-01 实测）：站点首页返回 200，但内容是停服公告页；`/api/room_stat` 全部返回 404 `{"error":"Not found"}`（换任意房间号结果一致）；房间页 `/room/<rid>` 302 回首页。也就是说失败与房间无关，是数据源本身没了——代码里原来打出的 `room_not_found` 只是把「站点不可用」收敛成了最近的错误枚举。

**先核查了替代数据源，结论是没有可替代的匿名免费接口**（完整实测记录见 `docs/research/2026-10-01-douyu-daily-stats-sources.md`）：斗鱼官方公开接口只给房间实时快照（开播状态、热度、贵宾数、关注数、礼物价目表），没有当日区间聚合；斗鱼开放平台（open.douyu.com）的 API 目录逐条核对后没有任何统计 / 收益 / 收入类接口；斗鱼创作中心（mp.douyu.com）是官方唯一给出「每日弹幕数 + 每日预计收益」的地方，但 302 跳主播登录、只覆盖主播本人的房间；第三方数据站那头，头榜（toubang）已终止服务、小葫芦（xiaohulu）域名已废弃转卖，飞瓜 / 蝉妈妈只做抖音电商，B 站那批统计站只覆盖 B 站。因此不是「换一个 URL」，而是没有任何等价来源。

**下线是整体的**：删除取数模块 `lib/doseeing-api.js`、纯规则模块 `lib/today-stats.js` 及其三个单测；编排里的 `todayStatsPoll` 周期 alarm、`pollTodayStats` 取数、`clearTodayStats` 清理与装配根上的 `todayStatsApi` port 一并移除；弹窗的今日统计行与渲染函数、设置页的 `todayStatsEnabled` 开关、`ROOM_STORE_DEFAULTS.settings` 里的默认值都删掉；`manifest.json` 的 `host_permissions` 去掉 `https://www.doseeing.com/*`。删代码而不是留一份「休眠」实现在于：数据源是永久消失的，留着的模块只会在未来误导读者，且 host 权限必须跟着撤（留着就等于为一个永不调用的域名继续向用户索权）。

**对既有用户的两处兼容处理**（都不改变「功能已没了」这个事实，只为平滑升级）：一是存储里遗留的 `todayStats` 运行时键，由编排在 `onInstalled`（安装 / 更新都会触发）时清成 null，避免永远留在 `chrome.storage.local` 里；二是下线之前导出的配置文件里带着 `todayStatsEnabled` 字段，`lib/config-backup.js` 的校验是「未知设置键整份拒绝」，所以那条 schema 条目保留为「接受但忽略」——照常导入，导入后由房间库读侧（`_resolvedSettings`）抹掉，不再进快照与下一次导出。

## Considered Options

- **保留代码，只默认关闭开关**：改动最小、将来若找到新数据源可复用；但 host 权限要撤就得连取数一起废（撤了权限再打开开关只会失败），而权限不撤又等于为一个停服域名持续索权。以「休眠代码」形态保留两个模块与三个单测，未来真正要重启这条路时也几乎要重写（判定口径、错误模型都会变）。
- **换一个第三方数据站继续取数**：不动产品形态；实测没有可用的匿名免费站（见上），付费 / 需登录的那几家要么不覆盖斗鱼、要么口径不是「付费礼物金额」，等于把刚还清的技术债换成新债。
- **改用斗鱼弹幕 WebSocket 本地自算**：技术上可行（`lib/douyu-barrage.js` 已在用同一条通道），四个指标都能自己累计；但那是「另一个量级的工程」而非换接口——要为**每个在线房间全天保持长连接**（现架构只为少数盯守房间开长连接），且**无法回填**扩展启动前的当天数据，数字天然不完整。若将来要做，应作为新功能单独立项、另写 ADR，并明确「弹幕数从扩展启动时起算」这一口径差异。
- **只保留弹窗那一行、显示占位或错误态**：用户至少知道这个功能存在；但那是在展示一个永远没有数据的行，噪声大于信息。
- **把判定 / 取数模块挪进 `.scratch` 留档**：逆向探针确有先例（ADR-0007 的探针脚本）；但 `.scratch` 已 gitignore，等于删除，不如直接删干净、由 git 历史保留。

## Consequences

- 扩展的对外请求回到「只发往斗鱼 / B 站」，README 的隐私章节与 `host_permissions` 同步收敛到这一事实——用户更新扩展时不再有第三方域名授权，这是本次下线唯一可见的收益面。
- 弹窗在线列表少了一行，卡片信息回归「昵称 / 标题 / 分区 · 观众数」；设置页「刷新与采样」卡片少一个开关。
- 旧 ADR 里把「今日统计」当作在役功能提及的地方（0007、0008、0009、0011、0012）均为历史记录，不再回溯修改；涉及当前形状的描述以本条 ADR 为准。
- 该功能的取舍记录（为什么当初选 doseeing、为什么只对斗鱼取数、为什么只算付费礼物）仍保留在 ADR-0007 里，供将来若重启同类功能时参照。
- 若将来以本地自算重启，「今日统计」的四项口径需重新定义（尤其「无法回填」这一点会改变用户对数字的预期），并需要新的规则模块与单测。
