# 配置可整体导出/导入：rooms + categories + settings 存成带版本号的 JSON，导入经房间库整体替换

换电脑（或重装浏览器）后要能把手上的监控配置原样搬过去，因此新增「配置备份」：设置页底部一张卡片，导出把配置写成一份 JSON 文件下载，导入选文件后整份替换本机配置。这条功能把六件事同时钉死，它们互相牵制，合记一条 ADR。

**一、只导「配置」，不导「观测」。** 导出三样：`rooms`（房间与其 per-room 开关/参数）、`categories`（分类列表）、`settings`（全局设置项）。不导出 `streamers`（主播快照）、`todayStats`（今日统计）、`highlightWatermarks`（看点水位）、`notifiedRooms`（已通知记录）、`watchQueued`（盯守排队）、`popupCategoryId`（弹窗记忆）以及 `_firstRun` / `lastRefresh` / `biliPageChannelEnabled`（通道降级标记）。判据是「用户的意图」对「本机的观测结果」：房间、分类、开关是用户配的，搬过去仍成立；观测值换机器后由新机器重新轮询与采样即重建，且 A 机观测到的「今天弹幕多少条」被 B 机当成本机数据是串味。`settings` 里的 `openInCurrentTab` 虽是「这台机器的浏览习惯」，仍一并导出——「机器 A 什么样机器 B 就什么样」比维护一份「本机偏好」名单更可预期，也不给新设置项留漏网。

**二、格式是 JSON，带格式标识与版本号。** 文件形如 `{ "format": "douyu-extensions-config", "version": 1, "exportedAt": ..., "rooms": [...], "categories": [...], "settings": {...} }`。JSON 本身是纯文本、人能读能改、别的程序也能消费；`format` 让「选错文件」（选成别的 JSON）当场可辨，`version` 给将来格式变化留出「不认识就拒」的落脚点。不采用 ini / YAML 这类自定可读格式——要多写一套解析器、易错，且通用性更差。

**三、严格校验，整份拒绝。** 结构与类型必须对（`rooms`/`categories` 是数组、`settings` 是对象、`platform` 是已知取值、`roomId` 是纯数字字符串、`categoryId` 指得到文件内某分类、房间无重复），数值必须落在合法区间（如 `surgeMultiple` 1.1～10、`refreshInterval` ≥ 60），`format` 与 `version` 必须认识，settings 里出现未知键即拒。任一条不合即整份拒绝、本机一字节不动。缺键视为「用默认」：写进去的 settings 只含文件里有的键，其余由房间库读侧既有的 `ROOM_STORE_DEFAULTS` 补全（`_resolvedSettings` 本就是干这个的），因此手改的精简文件仍能导入。宁可不动，也不留半套配置。

**四、导入是整体替换，不是合并。** 文件里的 `rooms`/`categories`/`settings` 直接成为本机这三个键。理由是这与「把 A 机的配置搬到 B 机」的一句话语义完全一致、结果可预期；合并（房间按复合键去重、分类按名合并、设置按字段覆盖）的冲突规则无法一句话说清，结果依赖两台机器各自的存量，用户难以预料。

**五、归属：导入是一次房间库写入，导出的读侧无写。** 三个键（外加下方对齐的 `streamers`）的形状与变更归房间库（ADR-0003），因此导入落成 `RoomStore` 的一个新意图式操作，由设置页发消息、SW 路由到它执行——页面不直写 storage 的纪律不变。运行时键不属于房间库，导入时**由编排**在同一个消息处理里清空（键归属边界一行不动：谁拥有键谁清）。导出没有写，只有读：设置页本来就为渲染而持有房间库的只读快照，导出读它即可，不经 SW。

**六、`streamers` 按新房间列表对齐，其余运行时键整份清空。** 对齐口径与分类内重排一致：仍是房间的保留其快照、消失的丢弃、新增的补一个空占位。这既维持了四键的形状不变量（`rooms` 与 `streamers` 一一对应），也避免弹窗出现孤儿——弹窗按 `streamers` 里 `online` 的房间渲染、并不按 `rooms` 过滤，不对齐的话被替换掉的房间的旧快照会在弹窗里继续列出。编排持有的运行时键（今日统计、看点水位、盯守排队、弹窗记忆、`_firstRun`、`lastRefresh`）整份清空，`notifiedRooms` 随后按新房间预置（见下），由新配置在新机器上重新积累。**`biliPageChannelEnabled`（B站通道降级标记）不清**：它是桥接通道的键、不归编排，且导入后的通道收敛会立刻按最新配置重写它——清它只会白丢一次「未登录时被风控降级过」的记忆。

**导入成功后立即完整收敛。** 周期 alarm、盯守长连接、B站通道决策、开播轮询不会因存储变化而自动跟上——它们靠编排的消息入口与每轮轮询收敛。导入后复用 `PATCH_SETTINGS` 的那套收敛序列（基础 alarm + 通道 + 盯守 + 看点 + 今日统计 + 一轮轮询），否则最坏要等一个轮询周期（默认 60 秒，改大则更久）才看到正确状态、`refreshInterval` 的变更也要等下一个 alarm 才生效。

**导入不触发开播通知。** 文件里的房间一律预记入 `notifiedRooms`（与手动添加房间同一套做法），紧接着那一轮轮询不会把当前正在直播的房间当成新开播、推一屏通知；它们下播再开播时正常通知。

**没有回滚。** 确认弹窗列出「文件里有几个房间 / 几个分类」与「本机当前有几个房间会被覆盖」后执行；不自动下载备份、不做撤销按钮。理由是加一条退路要多维护一个存储键与一个恢复入口（或每次导入多下一个文件），而配置本身随时可再导出一份。

**落点：一个新纯模块 + 一个新消息类型 + 一张新卡片。** 序列化与解析/校验抽成零依赖的纯模块（`lib/config-backup.js`，照 ADR-0005「纯规则模块各自持有常量」），生产与测试共用；房间库新增导入操作；页面 → SW 新增导入消息类型；设置页底部新增「配置备份」卡片（与既有卡片同风格，不干扰房间管理区）。导出文件名带日期（`直播通知配置-<日期>.json`）。词汇表不加词条——「导出 / 导入」是功能名不是领域概念，加进 `CONTEXT.md` 会让词表掺进实现词。

## Considered Options

- **合并导入**（房间按 `platform+roomId` 去重、分类按名合并、设置逐字段覆盖）：能汇总两台机器的房间；但同一分类名两侧含义可能不同、同名不同 id 的分类要重新分配 id、冲突房间的 per-room 配置取谁的没有自然答案，结果难预料。故取整体替换。
- **连运行时快照一起导出**（`streamers` / `todayStats` 等）：导入后立刻看到上次的数据、界面不空；但观测值是「那台机器」的，且会与新机器的实时轮询打架（旧的「在线」可能与新配置无关）。故只导配置。
- **自定可读文本格式**（ini / YAML 风格、带注释）：更贴人工阅读；但解析器要自己写、边界多，且不如 JSON 通用。故取 JSON。
- **不校验直接写 / 超范围钳制、未知键忽略**：实现最少、容错高；但坏文件会把本机配置写成不可用状态，或把「手改坏了」静默变成一次改值，用户拿不到反馈。故取严格校验、整份拒绝。
- **导入前自动下载一份本机配置备份 / 「撤销导入」按钮**：有回滚材料；但前者每次导入多下一个文件，后者要多维护一个存储键与一个恢复入口。用户明确不要退路，确认弹窗写清会覆盖即可。
- **删除式替换**（先清空四键再写）：概念直白；但两次写之间存在「本机配置为空」的窗口，且白留一次无谓写入。故取一次写入。

## Consequences

- 房间库新增一个导入操作（三键 + `streamers` 对齐，一次写入）与对应消息类型；`test/room-store.test.cjs` 要扩写（对齐 streamers、清运行时键的边界在编排侧不算它）。
- 新增纯模块 `lib/config-backup.js`（构造导出对象：剥掉非持久字段如 `online`、把 settings 收敛成已知键；解析并校验导入文件）与测试文件 `test/config-backup.test.cjs`。
- 设置页新增「配置备份」卡片与交互（导出触发下载、导入选文件 → 读文件 → 校验失败就地报错 / 校验通过弹确认 → 发消息），`options.css` 补卡片样式。
- 导入会在编排侧清空它持有的运行时键并触发一轮完整收敛；这些键的归属不变（ADR-0003 的键归属声明照办，不新增存储键）。
- 分类的语义不受影响：导入只是把分类列表整体换掉，分类仍是纯组织维度（ADR-0008 第六条不变），不接进任何通知链路。
- 校验里的数值区间与本仓库既有钳制规则（`ROOM_STORE_SURGE_LIMITS` / `ROOM_STORE_MIN_REFRESH_INTERVAL`）同源；将来这些区间若调整，导入的校验要与之一致，否则会出现「能存进去却导不回来」。
- `version` 一旦随首个版本冻结，往后增删导出字段就需升版本号，并决定旧版本文件是否仍接受。
